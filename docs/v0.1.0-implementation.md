# v0.1.0 基础能力改造

## 开发前审查与迁移约束

本轮范围：会话级精确选择、三级记忆检索、原页面局部更新，以及检索上下文预算。附件中的完整架构重建、侧边栏和设置页重排不自动纳入本轮。

保留：AES-256-GCM 安全箱、解锁期令牌复用、逐工作区授权/暂停/撤销、排除规则、敏感信息清理、提示词注入隔离、元数据审计、手动导入、来源/冲突/时间线、只读 DSH 同步及输入框上方功能栏。

现状缺口：当前会话只保存工作区 ID；检索是 BM25 与本地词法哈希向量混合，没有三级召回；上下文按字符截断；状态刷新已有桥接，但切换会话时请求竞争仍可能暂时保留旧状态。

兼容方案：安全箱格式及加密参数保持不变。新字段作为加密 state 的可选字段；旧 `workspaceIds` 精确迁移为这些工作区的 `all` 范围，不增加工作区；新会话仍默认关闭、空范围。三级派生文本只在内存中构建，可以从原文重建，不改写原始消息。不开启旧库的破坏性迁移，不读取或改写用户实际安全箱；回滚前保留加密文件副本，用原版本打开副本。旧版本不能识别会话细分范围，回滚时必须先关闭相关会话的记忆开关，防止旧版本恢复工作区级范围。

## 约束

- 可用来源列表不等于当前会话的检索选择；新增授权来源不自动进入当前选择。
- 每个来源显式选择 `all` 或 `sessions`；`sessions: []` 表示零会话，不能降级为全工作区。
- 筛选在服务端召回之前完成。派生内容沿用原记录的工作区、会话、风险和来源权限；跨源去重只合并当前已授权且选中的来源。
- L1 为已确认关键记忆或明确用户决策的原文摘录，保留确认状态；L2 为可追溯的抽取式摘要；L3 为原始消息片段。任何一层都不能绕过相关性门槛。
- 依据类问题显式检索 L3；L1 不足时依次回退 L2/L3。旧版本地词法向量不能宣称为神经语义 Embedding。
- 默认上下文预算 1,200 Token，预设 800/1,200/1,500；预算包含安全包装、来源、冲突提示和正文。无匹配 tokenizer 时使用明确标注的保守估算，不能报告为真实模型 Token 或宣称已节省计费用量。
- UI 只更新组件状态，不创建会话、不发送消息、不改变当前 Conversation ID；旧请求在会话/令牌/写入版本变化后不得覆盖新状态。

## 实现位置与数据模型

- `lib/core/scope.js`：统一校验与范围判断。安全箱仍为 state version 1，`sessionScopes[当前会话ID]` 新增 `selections` 与 `tokenBudget`。
- `lib/core/store.js`：加密保存选择，校验来源会话确实属于相应工作区；兼容旧工作区数组。
- `lib/core/layers.js`：缓存三个词法混合索引。L1 为 confirmed 的 decision/verified/preference 或用户明确表达的关键记录；用户记录仍保留原来的 unverified 状态。L2 为每条长消息的抽取式摘要，不进行跨工作区合成。L3 是原始消息索引。
- `lib/core/context.js`：测量完整输出文本，按完整句子装入预算，来源、确认状态、时间、可信度提示及安全包装一起计入。装不下的记录不生成虚假的引用标签。
- `lib/client.js`：来源会话列表、显式全范围开关、预算预设；请求按会话、令牌、写入代次隔离，保存期间不发状态轮询。

示例（工作区 B/C 是已授权的可用来源；当前会话只选择 B1/C3）：

```json
{
  "enabled": true,
  "workspaceIds": ["B", "C"],
  "selections": [
    { "workspaceId": "B", "mode": "sessions", "sessionIds": ["B1"] },
    { "workspaceId": "C", "mode": "sessions", "sessionIds": ["C3"] }
  ],
  "tokenBudget": 1200
}
```

`POST /secure-memory/api/session/:id/scope` 接受上述字段；新客户端以 selections 为准。`GET .../status` 返回已授权来源的已索引会话目录，不返回消息正文。新增授权来源不改变当前选择；会话未同步时可先刷新索引。无会话标识的文档仅能通过用户明确选择的 all 范围进入检索。

来源目录在本轮指已授权、已索引的来源列表，与实际会话选择分开；未新建附件中完整的“主工作区 → 关联目录”管理系统，也未改造侧边栏或删除旧管理页。

## 排序与权限

先在各层按工作区授权、会话选择、文档/会话/来源排除规则及敏感词过滤，再进行 BM25 + 本地词法哈希向量召回。相关性低于 0.18 的候选不获得层级加权；普通问题为 L1 加 0.30、L2 加 0.08。可用候选不足 2 条时继续下一层。原因、放弃、依据、原文等问题始终访问 L3，并为原文加 0.30。此为可解释启发式，不保证任意真实问题的语义召回率。

只合并内容相同的记录，并保留当前可访问的来源列表；不使用“文字大致相似”来删除可能包含不同项目或不同决策的依据。摘要继承原记录风险，敏感词检查使用完整原文。检索在审计 I/O 之后再次核对状态代次和权限；并发的撤销、锁定、范围变化、排除或敏感词修改会拒绝旧结果。安全箱变更也清除内存索引及最近来源缓存。

## Token 计量边界

默认 `estimateTokens()` 使用 UTF-8 字节数作保守估算；它不是 DeepSeek tokenizer，不是服务商账单。`metrics` 返回 budgetTokens、retrievedTokens、injectedTokens、tokenCounter、exact 及字符数。injectedTokens 测量实际渲染的参考块，包含安全说明/来源/冲突提示；不包含宿主额外添加的工具协议 framing 或其他对话消息。预算控制同时保留旧字符上限。

可向 `SecureMemoryService` 构造器传入同步 `countTokens(text)` 和匹配模型版本的 `tokenCounter` 标识，接入真实 tokenizer。默认发布入口尚未绑定具体模型 tokenizer，故默认 exact=false。精确计数器的正确性由集成方确保；模型服务商实际请求 usage 尚未接入，不能宣称实际节省某个百分比。

官方 [Token 计量文档](https://deepseek-harness.github.io/deepseek-harness/reference/subsystems/token-meter) 区分 usage 锚点与 estimated，并将 estimateMessage 定义为启发式接口；没有将它冒充为任意文本的精确模型 tokenizer。数据读取沿用官方 [会话只读持久化](https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/persistence.md) 与 [工作区服务](https://deepseek-harness.github.io/deepseek-harness/reference/subsystems/workspace)，UI 沿用 [Client Slots](https://deepseek-harness.github.io/deepseek-harness/reference/subsystems/slots)。

命令：

```text
node --test test/core.test.js test/no-session-creation.test.js test/tool-conflicts.test.js test/v010.test.js test/client-state.test.js
node scripts/benchmark-v010.mjs
```

29 项测试全部通过，包括原有安全/HTTP/加密/导入回归，以及会话精确筛选、空选择、解锁后保存、L1 优先、L2/L3 回退、原文敏感词对派生内容的限制、三种预算、迁移、并发排除拒绝旧结果。组件行为测试执行实际事件处理函数与延迟 HTTP 响应，验证原会话路径不变、切换会话丢弃迟到响应、轮询不能撤回范围保存。

Windows 沙箱曾阻止临时文件原子 rename 和 loopback 连接；上述回归在获准的沙箱外执行，仅使用临时合成数据，没有打开真实用户保险库。未在用户当前 DSH 窗口安装/热加载本次版本，也未进行真实宿主视觉点击验收。

合成基准：80 条记录、40 个标注问题；本次运行索引构建 29.21 ms，召回及上下文组装 P50 0.79 ms / P95 1.92 ms；Recall@4、关键记忆 Top1、最终上下文来源命中率和范围正确率均为 100%，同来源重复比例 0%。最终注入保守估算均值 1,052.38，最大 1,168，小于 1,200 预算。结果只代表这一小组合成样本，不代表真实用户数据或通用检索质量。

对比脚本同时报告旧式原文正文基线（上限 8,000 字符、单条 1,600 字符）的字节估算；旧基线不含完整安全包装，新值包含完整包装，因此不将其比值报告为实际 Token 节省率。模型实际 usage 为 null。未测量真实增量索引耗时；当前原文 revision 跳过机制保留，派生内存索引仍在安全箱变更后重建。
