新增核心测试：

1. **会话关联独立于授权**
   - 授权 A/B/C，当前会话只选 A。
   - AI 检索只能返回 A。
   - 显式请求 B → `UNAUTHORIZED_SESSION_WORKSPACE`，不返回数据。
   - 第二个会话 disabled → `SESSION_DISABLED`；独立启用 B 后只返回 B。
   - 未授权 workspace 不能写入会话 scope。
2. **会话 scope 持久化与撤销清理**
   - 锁定/解锁后 scope 保留。
   - 撤销 A 后，所有 session scope 中 A 自动移除。
3. **旧 v0.0.1 数据迁移**
   - 删除 `sessionScopes` 字段模拟旧 vault。
   - 重新解锁后 workspaces/docs 数量、ID 保持不变。
   - 默认会话 scope 为 `enabled=false, workspaceIds=[]`。
4. **Session status/scope HTTP API**
   - 无 Bearer → 401。
   - status 不包含文档正文。
   - scope 写入未授权 workspace → 403。
5. **静态“不新建会话”守护**
   - 扫描 `lib/client.js` 与 `lib/assets/app.js`。
   - 禁止 `startSession`、`forkSession`、`openSession`、`connectWorkspace`、`sessionController`、`session.prompt`、`sessions.fork`、`window.location=`、`location.href=`、`history.pushState`、`window.open`。
   - 禁止浏览器 token 存储（localStorage/sessionStorage/cookie）。
6. **Tool 名称冲突**
   - 原名空闲 → 保留 `xw_memory_*`。
   - `xw_memory_search` 被占用 → 自动使用 `cwm_memory_search` / 序号。
   - 不覆盖其他插件；记录冲突。
7. **UI slot 约束**
   - 主栏必须注册在 `conversation.input.dock`。
   - 存在 `conversation.composer.dock` 备用。
   - id 使用 `cwm-main-bar-v2`。
   - 不把 `defaultRetrieval` 当作会话关联。

## 3. 主界面操作验收清单

以下操作在代码层面只更新 React 状态/本地 API，不调用会话创建或消息提交：

1. 开启跨工作区记忆 → `POST /session/:id/scope`
2. 选择工作区 A → 同上，workspaceIds 变更
3. 增加 B → 同上
4. 取消 A → 同上
5. 关闭索引/总开关 → 同上，enabled=false
6. 再次开启 → 同上
7. 收起功能栏 → 本地 `expanded=false`
8. 重新展开 → 本地 `expanded=true`

代码级保证：

- 不调用任何 DSH 会话创建/fork/prompt/URL/history API（静态测试通过）。
- 当前 sessionId 只作为 API 参数/显示指纹；不会被修改。
- 功能栏不触碰消息列表或输入框内容。

**未做**：自动化浏览器像素级点击测试。当前环境没有可用的浏览器自动化控制；因此“当前会话 ID 在真实点击中保持不变”需要用户在刷新后的 GUI 中做一次可视化确认。静态检查与 slot 注册证明插件代码没有创建会话的调用。

## 4. 检索状态与来源验证

`sessionStatus` 返回：

- `retrieval.state`: `disabled | idle | retrieving | completed | no_results | denied | error`
- `resultCount`
- `sources[]`: 工作区、来源引用、标题、时间、分类、状态、可信度、风险
- 不含正文、token、口令、完整会话 ID

Host Tool 检索时会写内存状态；功能栏 3 秒轮询读取。status 轮询在 Host 上**不延长 token/vault idle**。

## 6. 兼容性 / 回滚

- 数据目录、vault/audit 格式、KDF、审计链、grant/docs 结构不变。
- `sessionScopes` 是可选增量字段；旧 vault 自动补空对象。
- v0.0.1 回滚会忽略该字段，不破坏已有数据。
- Settings 页保留，Tool 名称默认不变（仅冲突时改用 `cwm_*`）。
- 主功能栏异常时可降级到 composer dock 或 Settings。

---

## 7. 已知限制

1. 官方 Client slots API 不提供 occupants 枚举，无法检测其他插件占用的 slot/命令/快捷键；只能做唯一命名、Tool 名检测和自身降级。
2. 主 slot 1.5 秒未挂载才尝试备用位置，是启发式；极端慢加载可能导致备用/主位置都出现（list slot 可共存，不会覆盖）。
3. 不保存口令；页面刷新/DSH 重启后必须重新解锁。这是安全取舍，不是缺陷。
4. 无自动化浏览器点击测试；需用户在 GUI 中确认视觉与 sessionId 不变。
5. 未实现 OS 凭据管理（DPAPI/Keychain）自动解锁。
6. 现有 v0.0.1 的其余限制（无云工作区 API、SSD 擦除、防回滚等）继续适用。

---

## 8. 结论

- **数据与权限安全机制未被削弱**；会话选择是额外收窄。
- **主界面功能栏已注册到输入框上方**。
- **授权与本次会话关联已分离**。
- **代码中没有新建会话/导航路径**；原有“新建对话”现象无法从 v0.0.1 代码复现，若升级后仍出现，应按宿主/其他插件问题捕获现场。
- 可以交付为 **v0.0.2 本地预览版**，但真实点击验收与 iframe 视觉确认必须在用户 GUI 中完成。
