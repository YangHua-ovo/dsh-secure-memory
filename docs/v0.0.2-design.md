## 2. 授权 vs 本次会话关联

两个独立概念：

| 概念 | 存储 | 作用 |
|---|---|---|
| 工作区授权 `grants` | 加密 state，现有 | 允许插件访问该工作区 |
| 本次会话关联 `sessionScopes[sessionId]` | 加密 state，新增 | 当前会话允许 AI 检索哪些已授权工作区 |
| 本次会话启用 `enabled` | `sessionScopes[sessionId].enabled` | 当前会话总开关 |

规则：

- `enabled=false`：AI Tool 拒绝检索；即使其他会话已启用。
- `workspaceIds` 只能是**当前有效 grant** 的子集；不能借会话选择授权。
- 新建会话默认：`{ enabled: false, workspaceIds: [] }`。不继承全局默认，不继承其他会话。
- 已授权 A/B/C，当前会话选 A/C → B 不参与评分、上下文、图谱、状态来源。
- 取消 A → 后续检索不得返回 A。
- 撤销/过期 A → 所有会话的 A 自动失效；存储层可清理引用。
- 暂停 A → 会话选择保留，但 A 不参与检索；恢复后重新参与。

### 2.1 数据结构

```jsonc
// state.sessionScopes (optional, additive)
{
  "session-25e5...": {
    "enabled": true,
    "workspaceIds": ["ws_dsh_...", "ws_..."],
    "updatedAt": "2026-11-08T..."
  }
}
```

- 不改变 `STATE_VERSION`；旧 state 无此字段时按空对象初始化。
- 旧版本读取/回滚时忽略该字段，不会破坏原数据。
- 条目只记录 ID、enabled、时间；不记录检索内容。
- 会话 ID 只作 KV key；不写入日志原文（审计用 hash）。

## 3. Host API 增量

所有新接口都在 `/secure-memory/api` 下，保持回环 + Bearer + Origin/Host 检查。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/session/:id/status` | 会话开关、可选工作区、索引状态、检索状态、冲突 |
| POST | `/session/:id/scope` | 保存本次会话选择 `{enabled, workspaceIds}` |
| POST | `/session/:id/sync` | 只同步本次关联的 DSH 本地工作区 |
| GET | `/conflicts` | 只读插件冲突/降级状态（也可包含在 status 中） |

### 3.1 status 响应摘要

```jsonc
{
  "session": { "idHash": "...", "enabled": true },
  "scope": { "workspaceIds": ["ws_a"], "effectiveWorkspaceIds": ["ws_a"] },
  "workspaces": [
    {
      "id": "ws_a", "title": "AI Agent", "kind": "dsh-local",
      "authorized": true, "active": true, "paused": false,
      "selectable": true, "selected": true,
      "documents": 12, "lastSyncAt": "2026-...",
      "canSync": true
    }
  ],
  "counts": { "authorized": 3, "selected": 2, "selectedDocuments": 28 },
  "retrieval": {
    "state": "completed",
    "at": "2026-...",
    "resultCount": 4,
    "sources": [
      {
        "workspaceId": "ws_a", "workspaceTitle": "AI Agent",
        "sourceRef": "dsh-session:...#seq:...",
        "createdAt": "...", "category": "decision",
        "status": "confirmed", "confidence": 0.82
      }
    ]
  },
  "security": { "auditIntact": true, "locked": false, "autoLockMinutes": 30 },
  "conflicts": []
}
```

不返回正文、口令、token 或完整会话 ID。

### 3.2 scope 校验

```text
Bearer 有效
  → 会话 ID 合法
  → workspaceIds 去重、≤64
  → 每个 ID 必须是当前有效 grant（未暂停、未过期）
  → 否：403 UNAUTHORIZED_SESSION_WORKSPACE（不静默过滤）
  → 写 state + 审计 session.scope
```

### 3.3 检索运行时状态

Host 内存 Map（不持久化）：

```js
sessionRuntime = {
  sessionId: {
    state: 'retrieving' | 'completed' | 'no_results' | 'denied' | 'error' | 'idle',
    at, queryHash, resultCount, reason,
    sources: [{ workspaceId, workspaceTitle, sourceRef, createdAt, category, status, confidence }]
  }
}
```

- Tool 开始检索：`retrieving`
- 有结果：`completed` + 来源摘要（不含正文）
- 无结果：`no_results`
- 拒绝：`denied` + reason
- 异常：`error`
- 用户改 scope：`idle` / `disabled`
- 锁定：清空/锁定状态

## 4. Agent Tool 行为变更（安全收窄）

`xw_memory_search` / `xw_memory_context`：

```text
exec.agent.session.id
  → 读 sessionScopes[sessionId]
  → enabled?  否 → denied SESSION_DISABLED
  → 取有效 grant 交集
  → 空 → denied NO_SESSION_WORKSPACES
  → Tool 显式 workspaceIds?
        必须是 effective 子集，否则 denied UNAUTHORIZED_SESSION_WORKSPACE
  → 只在 effective 内检索
```

- 手动 Settings 检索（actor=`user-ui`）仍可按全部有效授权检索；它不冒充当前会话 AI 检索。
- `status` Tool 增加当前会话 enabled/selected 信息。
- 拒绝文案明确：“请让用户在上方功能栏选择工作区；AI 不能自行启用或扩权”。

这是**权限收窄**：v0.0.1 的授权、审计、高风险隔离、排除规则、来源追踪全部保留。

## 5. 当前会话内局部刷新

### 5.1 不新建会话的技术约束

- Client 只调用本地 `/secure-memory/api/...`。
- 状态更新走 React `useState` + 重新 fetch status。
- **禁止**：
  - `ctx.sessions.fork`
  - `ctx.uiWorkspace.startSession/connectWorkspace/openSession`
  - `session.prompt` / 任何消息提交
  - `window.location` / `history.pushState`
  - 通过 iframe 改变父页面 URL
- 不重建当前 conversation；只重渲染功能栏组件。
- 组件内记录 `sessionId`，变化只更新显示，不触发会话创建。

### 5.2 轮询

- 当已解锁且 `enabled=true`：每 3 秒 `GET /session/:id/status`。
- 页面不可见时暂停轮询；可见时立即刷新。
- 轮询只读，不写审计正文；不触发 Tool。
- 用户操作（toggle/选择/同步/锁定）后立即刷新，不等待轮询。

### 5.3 验收

在同一会话连续 toggle、选 A、加 B、取消 A、关闭/开启、收起/展开，`sessionId` 不变，消息列表不变，无新会话。功能栏状态由本地 state + status API 同步。

## 6. 密码/解锁体验

### 6.1 不能做的事

- 不保存明文口令。
- 不把口令写入配置文件/日志。
- 不把 Bearer token 写入 localStorage/sessionStorage。
- 不关闭身份验证。

### 6.2 本次实现

- 功能栏提供内联解锁（密码框 + 解锁按钮）。
- 解锁后的 Bearer token 保存在 **Client 插件模块闭包**，不在 React DOM/Storage/日志中。
- 在同一 DSH 页面运行期间：
  - 切换会话、收起/展开功能栏、切换 section 不需要重新输入。
  - Host vault 继续按现有 30 分钟空闲锁定（可在设置调整 1–240 分钟）。
- 页面刷新 / DSH 重启 / Host 锁定 → 需要重新解锁。
- Settings iframe 可通过 `postMessage`（同源、source=parent）接收父页面的内存 token，避免“主界面已解锁、设置又要求输入”；iframe 自身不会把 token 写入 Storage。
- 高风险操作（撤销全部、删除保险库）保留明确确认框；不会因缓存 token 自动执行。

### 6.3 为什么不做“永久记住密码”

没有安全的跨重启密钥保管实现（OS Credential Manager/DPAPI）时，保存口令或可解密密钥会降低安全等级。v0.0.2 不这样做；文档明确“本次运行免重复输入，刷新/重启需重新解锁”。后续可评估 OS 凭据管理。

## 7. 插件冲突检测与自适应

### 7.1 官方能力边界

- Host：可以通过 `ctx.tools.get(name)` 检查 Tool 名称占用。
- Client：`ctx.slots` 官方服务只暴露 `register` / `inject` / `registerFactory`，**没有公开的 occupants 枚举 API**。
- 因此：
  - 可以检测 Tool 名称冲突；
  - 不能可靠读取其他插件占用的 slot 列表、命令、快捷键、事件监听器；
  - 不读取其他插件私有数据，不修改其他插件，不强制覆盖。

### 7.2 实现

- Tool 名称：
  - 默认仍用 `xw_memory_*`，保持兼容。
  - 注册前 `ctx.tools.get(name)`；若被占用，改用 `cwm_memory_*`（仍冲突则加序号）。
  - 记录 `conflicts[]`，在功能栏/设置中显示。
  - 不覆盖现有 Tool。
- UI：
  - 主功能栏使用唯一 id `cwm-main-bar-v2`，类名统一 `cwm-`。
  - `conversation.input.dock` 是 list slot，多个插件本来就是共存关系；不强制替换。
  - 主 slot 在 1.5s 内未挂载 → 尝试 `conversation.composer.dock`；仍不可用 → Settings iframe 作为最终降级。
  - 由于官方无 occupants API，无法证明“其他插件是否占用同一位置”；只报告自身挂载位置与降级状态。
- 命令/快捷键/事件监听：
  - 本插件不注册 DSH 命令、快捷键或全局事件监听；没有相应冲突面。
  - 不声称检测了其他插件的这些资源。

### 7.3 自适应状态

- `surface`: `input-dock` | `composer-dock` | `settings-only`
- `compact`: 宽度 < 560px 或用户手动收起
- `toolNames`: 实际注册名
- `conflicts`: 数组（仅限可证实项）

## 8. 检索状态与来源

功能栏状态：

- 未启用
- 已启用 · 待检索
- 正在检索
- 检索完成 · N 条
- 暂无相关记忆
- 未选择工作区
- 未授权
- 审计异常
- 检索服务异常
- 插件冲突/降级

来源面板显示：

- 工作区名称
- 来源引用（session ID 截断 + seq）
- 记忆生成/事件时间
- 分类 / 状态
- 可信度提示
- 不显示正文，除非用户打开结果面板

这些信息来自 status runtime 的 `sources`（不含正文）。

## 10. 兼容与回滚

4. 若功能栏异常，可仅停用主界面入口，保留 Settings（代码内已有降级）。

## 11. 测试计划

1. 基线 13 项全部通过。
2. 会话级：
   - 授权 A/B/C，scope A/C，AI 检索不返回 B。
   - Tool 显式请求 B → denied。
   - scope disabled → denied。
   - 两个 session 独立，不串。
   - 撤销 A → 所有 scope 中 A 失效。
   - 重新 unlock → scope 持久化。
3. API：
   - 无 Bearer 401。
   - 未授权 workspace 403。
   - status 不含正文/token。
4. 回归：授权、同步、检索、撤销、删除、来源、加密、过滤、审计。
5. 静态：客户端无会话创建/导航调用。
6. 冲突：mock `ctx.tools.get` 占用原名，断言改用 `cwm_`。
7. UI 验证：主 slot 注册、设置页保留、CSP；真实浏览器交互需用户确认。
