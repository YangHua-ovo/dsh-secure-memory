# v0.0.2 前置分析：v0.0.1 代码、UI、会话与“新建对话”根因

- 分析对象：`E:\工程\Memory\v0.0.1` 当前代码
- 基线日期：2026-11-08
- 基线测试：`node test/core.test.js` → **13/13 通过**
- 目标：在不破坏数据、授权和安全机制的前提下，把日常操作迁移到对话输入框上方，并实现会话级工作区关联。

## 1. 当前功能模块清单

| 模块 | 文件 | 现状 |
|---|---|---|
| Host 入口 | `lib/index.js` | 初始化加密 store、注册 Tool、注册本地 HTTP 路由；无会话创建 |
| 加密保险库 | `lib/core/vault.js`、`crypto.js` | scrypt + AES-256-GCM；密钥只在 Host 内存 |
| 状态/授权/审计 | `lib/core/store.js` | 工作区、grant、docs、排除规则、审计；状态与审计分开加密 |
| 检索 | `lib/core/retrieval.js` | BM25 + 本地字符 n-gram 向量；权限集合先于评分 |
| 校验 | `lib/core/validate.js` | 可信度提示、时间、冲突；启发式 |
| 上下文 | `lib/core/context.js` | 安全边界、转义、高风险隔离 |
| DSH 接入 | `lib/core/ingest.js` | 只读 `workspaceRegistry` / `sessionPersistence` |
| Host API | `lib/server/routes.js` | 本地回环 + Bearer + Origin/Host 检查 |
| Agent Tool | `lib/tools.js` | search/context/status；无授权/撤销/删除 Tool |
| Settings UI | `lib/client.js` + `lib/assets/*` | `settings.section` 内嵌 iframe |

当前 13 项测试覆盖：加密、错误口令、DSH 最小读取、授权前检索、未授权拒绝、撤销、临时到期、注入隔离、闭合标签转义、审计篡改、导入、排除规则、秘密脱敏、HTTP 鉴权、CSP。

## 2. 当前 UI 结构

```text
DSH Settings
  └─ settings.section (list)
       └─ secure-memory (order 46)
```

  - `todo` (order 0)
  - `goal` (order 10)
  - `queue` (order 20)

**目标位置已确认存在**：`conversation.input.dock`，scope `session`，标准 props 包含 `sessionId`、`useSession`、`useConversation` 等。备选位置为 `conversation.composer.dock`（输入框下方）和 `settings.section`。

## 3. 当前插件生命周期

```text
DSH boot
  → apply(ctx)
      → SecureMemoryStore.initSync()
      → new SecureMemoryService(...)
      → service.start()（30s 检查空闲锁定）
      → ctx.webServer.register('/secure-memory')
      → registerTools(ctx, service)
      →（客户端）注册 settings.section iframe
  → 用户操作
      → iframe fetch 本地 API
      → service → store → 加密写盘 / 审计
  → 插件卸载
      → service.dispose() → store.lock()
```

没有调用：
- `ctx.sessions.fork`
- `ctx.uiWorkspace.startSession`
- `ctx.uiWorkspace.connectWorkspace`
- `SessionController.create`
- `session.prompt`
- `window.location` / `history.pushState`
- 任何“提交消息”接口

## 4. 当前状态管理方式

| 状态 | 位置 | 持久化 |
|---|---|---|
| 保险库解锁/锁定 | Host `SecureMemoryStore` | 否（密钥仅内存） |
| 工作区授权 | 加密 state `grants` | 是 |
| 工作区/文档 | 加密 state | 是 |
| 当前默认检索标记 | `grant.defaultRetrieval` | 是 |
| 设置 | 加密 state `settings` | 是 |
| 检索结果 | 请求响应；UI 内存 | 否 |
| 审计 | `audit.enc` | 是 |
| 管理令牌 | Host 内存 Map；浏览器 JS 内存 | 否 |

**没有会话级工作区关联状态。** 当前 AI Tool 使用 `defaultRetrieval` 的已授权工作区；这意味着“授权过”会在所有会话中默认可用，正是本次要修正的问题。

## 5. 当前会话 ID 获取和管理方式

- Host Agent Tool：`exec.agent?.session?.id`（`agentSessionId`）。
- Client 输入框上方 slot：标准 `sessionId` prop。
- 当前 Settings iframe：**拿不到会话 ID**，所以设置页只能做全局授权/管理，不适合做会话级选择。
- 插件没有任何修改或创建会话 ID 的代码。

---

## 6. 当前设置与密码验证机制

- 口令 → scrypt → 32 字节 vault key；AES-256-GCM 解密 state。
- 解锁时 Host 生成随机 Bearer token，保存在内存 Map。
- 浏览器 token 只存在 iframe 的 JS 变量；刷新 iframe 或重新打开设置会丢失，需要重新输入口令。
- 没有保存口令；没有 OS 凭据管理；没有明文 token 落盘。
- 空闲自动锁定；锁定时 token 全部清除。
- 所有数据 API 需要 Bearer；`setup/unlock` 需要本地回环 + Host/Origin 检查。

**体验问题根因**：不是密码验证错误，而是 token 生命周期绑定到了 iframe 页面，而不是整个 DSH 页面运行期。把 UI 迁到主界面后，token 可保存在 Client 插件模块闭包中，切换会话/收起功能栏不需要重新输入；刷新整页仍需重新解锁。

---

## 7. 当前索引和授权机制

- 授权：`store.grant` 写加密 state。
- 索引：`syncWorkspace` 只读 DSH session，按会话替换文档；不触碰原始数据。
- 检索：`_scope()` 取 grant → 再构造候选集。
- 撤销：删除该工作区 docs/sessions/grant。
- 当前 `_scope()` 没有 session 维度，因此：
  - AI Tool 默认使用 `defaultRetrieval`。
  - 无法表达“已授权 A/B/C，但本会话只用 A/C”。

## 8. “操作后新建对话”根因调查

### 8.1 代码事实

对 `lib` 全量静态扫描，唯一包含 `prompt` 的位置是：

```text
lib/assets/app.js: window.prompt('这将删除密文...请输入 DELETE 确认')
```

这是删除保险库的确认框，不是会话创建。

未发现：

- `startSession`
- `connectWorkspace`
- `openSession`
- `forkSession`
- `session.create`
- `session.prompt` / 消息提交
- `window.location =`
- `location.href =`
- `history.pushState`
- `window.open`

Settings iframe 中的表单都调用了 `event.preventDefault()`；`renderShell`/`loadState` 只更新 iframe DOM，不操作父窗口。

### 8.2 结论

**v0.0.1 的插件代码没有创建新会话的路径。**  
因此“切换开关/切换功能栏后新建对话”不可能由当前插件的这些代码直接触发。可能的来源是：

1. DSH 宿主对 Settings 面板或某个 UI 操作的自身行为；
2. 另一个同时安装的插件；
3. 用户实际操作的是另一个按钮/入口；
4. 浏览器扩展或主题脚本。

在没有捕获到实际点击与 DSH session 日志之前，不能把根因安在某个插件身上，也不应该用隐藏新对话的方式掩盖症状。

### 8.3 v0.0.2 的应对

- 主界面功能栏只调用：
  - `fetch('/secure-memory/api/session/...')`
  - React 本地 state / CSS
- 不调用任何 DSH session 创建、fork、prompt、URL/history API。
- 在功能栏开发详情中显示当前 `sessionId` 指纹，便于验收“会话 ID 不变”。
- 增加静态回归测试：扫描客户端代码，禁止上述会话创建/导航 API。
- 若升级后仍出现新会话，需要捕获具体点击时刻的 DSH 会话日志与操作者；那将是宿主/其他插件的问题，而不是本插件 UI 的隐藏行为。

## 9. 本次升级必须保持的不变量

1. 数据目录与加密格式不变；`sessionScopes` 是可选增量字段。
2. 旧保险库可无损解锁；旧字段全部保留。
3. 授权仍由用户显式操作；会话选择不能授权。
4. `_scope` 仍然先鉴权再检索；新增会话约束是进一步收窄，不是放宽。
5. 高风险隔离、审计、CSP、Host/Origin/Bearer 检查全部保留。
6. Tool 没有授权/撤销/同步/删除能力。
7. UI 操作不提交消息、不创建会话、不改当前 session ID。
8. 现有 Settings 页面保留，作为首次设置、授权、删除和审计管理入口。
