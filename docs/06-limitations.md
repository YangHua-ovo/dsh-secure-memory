# 已知限制与后续规划

## 1. 官方能力限制（不可由本插件解决）

1. **没有 DeepSeek 云工作区读取 API。** 不能自动读取云聊天历史；只能用户手动导出后导入。
2. **没有云聊天插件上下文注入 API。** 本插件只在 DSH 内提供 Tool 和设置界面，不能向 DeepSeek 网页对话注入。
3. **官方导出格式可能变化。** 本插件尽力解析常见 JSON/Markdown，但不保证所有历史版本格式；不支持 ZIP/二进制。
4. **云聊天没有逐工作区 OAuth。** 本插件的“授权”只在本机 DSH 进程内有效，不代表 DeepSeek 云端授权。

## 2. 数据源限制

1. **DSH 本地工作区 ≠ 云工作区。** 列表来自 `workspaceRegistry` 的本地目录；会话来自本地 `sessionPersistence`。
2. **只索引文本块。** 不索引系统提示、开发者消息、推理内容、工具调用参数/结果、图片、附件。
3. **单会话只读最近 4,000 个事件。** 超出会警告；不是全量归档。
4. **不做后台持续同步。** 需用户点击“同步索引”；这是有意的隐私/资源选择。
5. **手动导入是快照。** 后续 DeepSeek 云端变化不会自动进入；需要重新导出/导入。
6. **当前工作区自动识别未接入设置页。** UI 无法从 root-scoped 设置页可靠取得当前会话的 workspace；用户可手动取消选择。AI Tool 的审计包含当前会话哈希，但不自动排除当前工作区。

## 3. 检索与知识质量限制

1. **不是神经语义 Embedding。** 当前“向量”是本地字符 n-gram 哈希向量，优势是零外部传输和零依赖；不能理解同义词/跨语言语义。
2. **BM25 + 哈希向量可能漏召回。** 长文档未分块，宽泛查询可能返回粗粒度结果。
3. **知识图谱是共现关系。** 主题标签来自词频启发式，不是实体链接、因果推理或事实验证。
4. **可信度是启发式提示。** 不是事实正确率，不能替代人工确认。
5. **冲突检测是启发式。** 只对“已确认/已验证 + 共同主题 + 低相似度 + 跨工作区”做提示，可能漏报/误报；不自动裁决。
6. **分类/状态自动推断有限。** 同步得到的消息默认 `unverified`；需要人工确认最终决策。
7. **搜索有上限。** 3,000 文档/工作区、10,000 文档/全库；达到上限会拒绝或截断并提示。

## 4. 安全边界与限制

1. **单用户、单 profile。** 数据隔离基于 OS 用户 + DSH profile + 口令；不是多租户服务。
2. **OS 用户即信任边界。** 能读取 DSH 进程内存、浏览器内存或注入进程的恶意软件不在防御范围内。
3. **回环 HTTP。** 管理面只允许 127.0.0.1/localhost/[::1]；自定义域名或远程暴露会拒绝。若未来支持远程，必须重新设计 TLS/认证。
4. **不能承诺物理擦除。** SSD 磨损均衡/文件系统快照可能保留旧密文块；删除会移除文件与密钥。
5. **无防回滚锚点。** 有文件系统写权限的攻击者可以把 `vault.enc`/`audit.enc` 回滚到旧版本；HMAC 链不能发现整文件回滚。需要外部单调计数器/可信时间戳才能解决。
6. **审计与状态是两个加密文件。** 状态先写、审计后写；解锁时会比较时间戳发现“状态新于审计”的崩溃窗口，但不能保证 100% 原子。极端竞态/时钟回拨仍可能影响判断。
7. **无隐藏注入。** AI 自动检索是 Tool 驱动，不会在用户不知情时把记忆塞进每轮系统提示；这也意味着模型可能选择不调用 Tool。
8. **管理令牌在页面内存。** 页面刷新后需要重新解锁；不是持久登录。
9. **本地 HTTP 口令传输。** 口令从浏览器到同机 Host 通过回环 HTTP；未使用 TLS。远程访问被拒绝，但本机其他高权限进程仍可能嗅探/读取进程内存。
10. **AI 上下文会发送给模型服务商。** 这是使用记忆的必要传输；插件本身不联网，但 DSH 会把当前对话（含 Tool 结果）发给当前模型服务商。

## 5. 尚未实现（后续可做）

- 官方云工作区连接器（仅在官方提供公开 API/OAuth 时）。
- 可选本地神经 Embedding（如用户明确选择本地模型；仍不默认上传）。
- ZIP/更多官方导出格式适配。
- 加密 SQLite FTS/向量索引，以支持更大规模。
- 文档/消息分块与更好的重排。
- 外部审计锚定、防回滚单调计数器。
- 当前 DSH 会话工作区的自动识别与“排除当前工作区”开关。
- 定时同步/后台索引（必须默认关闭并单独授权）。
- 多用户/团队模式（不应在当前单机架构上伪装实现）。
- 图形化知识图谱布局优化、可访问性增强。
- 更细粒度的文件/对话/消息排除规则管理。

## 5.1 v0.0.2 新增限制

1. **Session scope 依赖 DSH sessionId。** 子智能体/非常规会话若没有正常 sessionId，会话级 Tool 会拒绝（安全默认）。
2. **Settings 手动检索仍是全局授权范围。** v0.0.2 的逐会话收窄针对 AI Tool；Settings 的“手动检索”是管理面，不使用当前会话 scope，避免 iframe 猜测 session。
3. **新会话默认关闭且空选择。** 这是刻意的安全默认；需要在输入框上方显式开启并勾选。
4. **Client slot occupants 不可枚举。** 只能通过唯一 id、Tool 名检测和可用性计时降级，不能声称检测了其他插件的全部 slot/命令/快捷键。
5. **1.5 秒主 slot 探测是启发式。** 极慢加载下可能同时显示主/备用位置；list slot 允许共存，不会覆盖其他插件。
6. **不保存口令。** 页面刷新/DSH 重启/宿主锁定后必须重新解锁；跨重启自动解锁需要 OS 凭据管理，本版未实现。
7. **无自动化浏览器点击验收。** 现有测试验证 Host、API、slot 注册、静态无会话创建；真实视觉与 sessionId 不变需用户在 GUI 刷新后确认。
8. **Tool 名冲突时自动改名。** 若使用 `cwm_memory_*`，模型提示/用户习惯可能需要适应；功能栏/Settings 会显示实际 Tool 名。
9. **sessionScopes 无独立清理 UI。** 撤销时清理对应 workspace，但不会主动删除所有旧 session key（后续可加压缩/清理）。
10. **Settings iframe 与主功能栏的 token 通过同源 postMessage 共享。** 已限制为唯一 Settings frame，但同一 DSH 页面中的恶意同源脚本仍属于宿主信任边界。

## 6. 版本兼容性

- 目标 DSH：0.2.x 系列（本环境实测 `tools.register`、`webServer.register`、`workspaceRegistry`、`sessionPersistence`、`conversation.input.dock`）。
- Node.js：>= 22.12（内置 `crypto.hkdfSync`、`fetch`、`node:test`）。
- v0.0.2 新增 `sessionScopes` 为可选字段，不改 `STATE_VERSION`；v0.0.1 数据可直接打开。
- 若 DSH 修改 Tool/Service/Slot 契约，需要重新验证并调整 `lib/tools.js`、`lib/index.js`、`lib/client.js`。
- 本插件不依赖第三方 npm 运行时依赖；这降低了供应链风险，但也意味着没有外部语义模型/数据库能力。
